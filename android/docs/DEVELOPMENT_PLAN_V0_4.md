# Android 구현 준비와 개발 순서 v0.4

현재 진행: M0 3탭, M1 지역 검색·저장, M2 실제 날씨, M3 지역 기본 추천, [M4 착장 8종](AVATAR_ASSET_IMPLEMENTATION_STATUS.md)에 이어 [M5 출퇴근·선택 민감도](PERSONALIZATION_IMPLEMENTATION_STATUS.md)를 연결했다. 장소·시각·다음 날 귀가·요일·독립적인 더위/추위·이동/실내 설정을 저장하고 예보별 차림에 반영한다. Android 테스트 61개, 빌드·lint와 실제 화면을 검증했다. 다음은 M6 구조화 피드백·기록이다. 자동 체감 학습과 자유 외형 꾸미기는 아직 없다.

기반 보완: [앱·서버 영속 캐시와 호출량 관리](CACHE_IMPLEMENTATION_STATUS.md)를 추가했다. 이후 백엔드는 [자원 사용 원칙](../../weather_api/DEVELOPMENT_RESOURCE_POLICY.md)을 따른다. 오늘의 운세는 [기획 후보](PRODUCT_IDEA_BACKLOG.md)로만 기록했다.

후속 전환: 사용자가 시안 검토 완료 후 제품 개발을 승인했다. [제품 개발 검토](PRODUCT_TECH_REVIEW.md)와 [데이터 경계 초안](DEVELOPMENT_CONTRACTS.md)을 바탕으로 Android 기능 단위로 검증한다. 초기 규칙의 개인 적합성은 검증 전이며 실제 체감·피드백 기능은 아직 없다.

2026-11-02. 아래 표는 초기 계획과 완료 기준이다. 실제 완료 범위는 위 최신 구현 결과를 따른다. 이전 개발 계획의 옷장·활동 점수는 초기 범위에서 보류한다.

## 구현 전 준비

| 단계 | 준비 내용 | 완료 판단 근거 | 현재 |
|---|---|---|---|
| 준비 A | 화면/명세 정합성 | 최신 시안 수정 사항·미작성 상태·취소/복귀 검토 | 주요 22상태 정적 시안, 세부 검토 남음 |
| 준비 B | 3D 토이 에셋 | 같은 인물의 의류 ON/OFF·종류·작은 화면 확인 | 스타일 선택됨, 제품 자산 검증 전 |
| 준비 C | 기능별 Android 흐름 검증 | 구현한 기능의 추천·대안·피드백·오류 복구를 실제 실행 | 아바타 표시 한 쌍 확인. 전체 제품 흐름 구현 전 |
| 준비 D | 날씨/추천 기술 명세 | 제공자 조건·항목·비용·캐시·범주/두께·근거 확정 | 미정. 기존 웹 재사용은 전제 아님 |

임의의 완료 날짜·기간·개발비를 정하지 않았다. 실시간 3D 도입은 필수 조건이 아니다. 시안 이미지는 최종 의류 자산이 아니다.

## 구현 순서 제안

기존 APP-00 이력을 유지하며, M 번호는 현재 컨셉에 맞춘 새 기능 묶음이다. 한 묶음을 완료·검증한 뒤 다음으로 진행한다.

| ID | 기능 | 완료 기준 |
|---|---|---|
| M0 | 골격 정리 | 오늘/시간별/설정 3탭, 자식 화면 Back·초안·스크롤 정책. 옷장 탭은 이 단계에서 정리 |
| M1 | 지역 검색·저장 | 결과 없음/실패/선택/복원. 위치 거부 시 수동 사용. 미입력 구분 |
| M2 | 실제 날씨·시간별 | 단위·지역·시각·출처 검증. 로딩/실패/이전 예보/부분 실패. 허위 예보 폴백 없음 |
| M3 | 기본 추천·이유·대안 | 종류·두께·탈착 규칙과 근거 일치. 부적합한 대안으로 칸을 채우지 않음. 계산 경계 검증 |
| M4 | 아바타 표현 | 승인 자산과 실제 착용 상태 일치. 작은 크기·미지원 의류 대체·오프라인 확인 |
| M5 | 출퇴근·선택 개인화 | 장소2·시각2, 자정 넘김, 선택 요일/이동/민감도 저장·복원. 미입력 정보 사용하지 않음 |
| M6 | 피드백·기록 | 착장/휴대·체감·강도·상황·불일치 구분. 초안·실패·중복·수정·삭제 확인 |
| M7 | 제한된 개인 보정 | 정한 범위 내 보정·설명 일치. 수정/삭제/초기화 후 중복 기여 없음. 개선 효과 검증 |
| M8 | 선택 알림 | 시간·요일·권한, 거부·재시작·갱신 실패 처리. 피드백 독촉 없음. 현실적인 전달 동작 확인 |
| M9 | 배포 준비 | 접근성·320dp·큰 글꼴·다크·실기기·릴리스 확인. 처리와 스토어 설명 일치 |

로그인·동기화·광고·위젯·개인 옷장·사진 기반 가상 착용은 후속 결정이다. 키 보호나 공용 캐시 서버는 계정과 별개로 도입할 수 있다. 기존 FastAPI/Supabase의 재사용 여부는 미정이다.

## 검증 방식

기능별 입력·상태·저장·실패를 먼저 명시하고 에뮬레이터에서 사용자 흐름을 실행한다. 정적 이미지 변경에 구현을 복제하는 테스트를 추가하지 않는다. 추천·시간·중복 저장·보정 등 계산과 데이터 경계는 의미 있는 테스트로 확인한다. 계획을 테스트 통과로 기록하지 않는다.

기존 APP-00 빌드·lint·4탭 전환은 2026-11-01 빈 앱의 이력이다. 현재는 3탭과 실제 날씨를 구현했고 ViewModel·DataStore·코루틴 의존성을 추가했다. 추천·피드백 구현 완료를 뜻하지 않는다.
