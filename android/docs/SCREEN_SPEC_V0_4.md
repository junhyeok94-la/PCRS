# 화면 동작 명세 v0.4

2026-11-02. [디자인 검토 모음](DESIGN_REVIEW_V0_4.md)을 기준으로 한 제안 명세다. 미확정 정책은 명시하며 앱 구현·실제 데이터 검증 완료로 해석하지 않는다. 이전 Figma 노드 ID와 독립된 화면 ID를 사용한다.

## 공통 규칙

루트 탭은 오늘 / 시간별 / 설정이다. 각 탭의 스크롤·선택 상태를 유지한다. 자식 화면에서는 탭을 숨기고 상단 뒤로 가기와 시스템 뒤로 가기를 같은 의미로 처리한다. 다른 루트에서 시스템 뒤로 가기는 오늘로 이동하는 기존 골격 동작을 기준으로 검토한다.

버튼은 최소 약 44dp 터치 영역을 확보하고 아이콘에 접근성 이름을 제공한다. 본문 축소로 화면을 맞추지 않는다. 큰 글꼴에서 칩·행을 줄 바꿈하고 차트는 데이터 목록으로도 읽을 수 있게 한다. 색·아이콘만으로 상태를 표현하지 않는다. 캐릭터 애니메이션은 필수로 두지 않는다. 모든 선택은 실제 데이터와 분리된 미선택 상태를 표현할 수 있어야 한다.

단위는 °C, m/s, %, mm로 명시하고 날짜·시간은 대한민국 기준으로 표기한다. 예보 기준 시각, 수신 시각, 피드백 경험 시각, 저장 시각은 서로 다르다. ‘오늘’은 해당 시점의 날짜와 연결해 저장한다. 시각만 같은 어제 기록으로 오인하지 않는다.

지역은 표시명과 제공자 조회에 필요한 식별 정보를 구분한다. 집·직장의 정확한 주소를 요구하지 않는다. 날씨 조회용 좌표의 정밀도·저장 범위는 제공자 선정 후 결정하며 지역 단위 저장 문구와 맞춰야 한다. 백그라운드 위치 추적은 현재 범위가 아니다.

| E4 | 경보/위험 기상 | 제공자가 지원하는 경보가 있을 때 | 옷 추천보다 앞에 지역·유효기간·출처 표시. 지원 범위 미확정 |

## 홈·대안·시간별

홈은 세로 스크롤이며 하단 탭은 시스템 영역과 겹치지 않게 고정한다. 아바타 카드 위 현재 날씨·시간별 요약, 아래 습도·바람·강수·UV·일출/일몰을 둔다. 지원하지 않는 항목은 0 대신 숨김 또는 제공 없음으로 표시한다. 미세먼지 추가는 별도 데이터 연동 결정 후다.

H0 기본 추천은 화면에 표시한 지역과 아침·저녁 구간을 사용한다. 늦은 저녁에 앱을 처음 열었을 때 지난 아침을 미래 추천으로 내보내지 않도록 대상 날짜·남은 시간대를 명시하는 규칙이 필요하다. 정확한 예보 구간과 추천 정책은 기술 검토에서 확정한다.

H2는 출근 출발 지역·시각과 귀가 출발 지역·시각을 각각 표시한다. 경로·도착 시각·실내 온도를 아는 것처럼 표현하지 않는다. 귀가가 자정을 넘으면 다음 날로 구분한다. 출근보다 이른 귀가 시각은 단순 입력 오류로 금지하지 않고 다음 날 귀가인지 확인한다. 두 장소가 같아도 허용한다. 요일 미입력은 미입력으로 보존한다.

A1은 적합한 대안을 최대 3개 제시하는 안이다. 한 개면 좌우 버튼/순서를 숨긴다. 목록 탐색은 미리보기이며 ‘오늘 이 차림으로’에서 후보만 확정한다. 피드백을 실제 착용 전에 성공으로 기록하지 않는다. 예보·설정 변경 시 이전 후보가 적용된 기준을 보존하고, 새 추천이 후보와 다르면 사용자에게 재확인하도록 한다. 조용히 다른 옷으로 덮어쓰지 않는다.

W2 장소 탭 변경은 그래프와 상세 목록을 동시에 바꾼다. 시간대·강수·풍속 단위를 일치시킨다. 두 장소 자료 중 하나만 실패하면 실패한 쪽을 표시하고 비교 추천이 완전한 것처럼 보여주지 않는다. 차트 세로축은 실제 데이터 범위를 사용한다. 선택 시간 상세는 호버 없이 탭/접근성으로 확인할 수 있어야 한다.

## 피드백 상태와 저장

[피드백 상세 설계](FEEDBACK_FLOW_DESIGN.md)를 따른다. 후보/추천 스냅샷은 작성 시작 시 고정하고 백그라운드 갱신으로 바꾸지 않는다. 시간·지역을 바꾸면 연결된 예보/추천도 확인하고 불일치한 이전 스냅샷을 그대로 확정하지 않는다. 연결할 자료가 없으면 경험만 기록했음을 구분하고 추천 성공/실패 자료로 학습하지 않는다.

기본 초안, 실제 차림 수정 초안, 불일치 수정 초안을 구분한다. 자식에서 확정하면 부모 초안만 갱신하고, 자식 뒤로는 그 자식의 미확정 변경을 취소한다. 부모에서 상세로 갔다 돌아오면 입력을 유지한다. 최상위 피드백을 닫을 때 입력이 있으면 임시 보존 또는 폐기 확인을 제공하는 안을 검토한다. 앱을 다시 열었을 때 이전 초안이 새 날의 경험으로 오인되지 않도록 날짜와 복원 여부를 확인한다.

더움↔추움 변경 시 이전 방향의 강도·상황을 그대로 적용하지 않는다. 방향별 초안 복원 여부를 명확히 하고 최종 기록은 선택한 방향의 항목만 반영한다. 적당함 선택 시 불편 강도는 기록하지 않는다. 없음·모름은 다른 항목과 동시 선택하지 않는다. 미응답은 없음으로 바꾸지 않는다.

중복 탭은 한 번의 저장으로 처리한다. 저장 실패 시 입력을 유지하고 같은 기록 식별자로 재시도한다. 수정은 기존 기록을 대체하고 이전 보정 기여를 제거한 뒤 반영한다. 삭제한 기록의 보정 영향도 남기지 않는다. 개인 보정 초기화는 기준 시점 이전 기록을 다시 읽어 자동 복구하지 않게 한다. 보정 알고리즘은 별도 검증 전이다.

## 권한·실패·데이터

현재 위치 버튼을 눌렀을 때만 위치 권한을 요청한다. 거부/찾기 실패 시 수동 검색을 그대로 제공한다. 검색 중·결과 없음·오프라인을 서로 구분하고 마지막 검색어를 유지한다. 지역 변경이 기존 경험 기록의 지역을 바꾸지 않는다.

알림을 켜려는 시점에 필요한 시스템 권한을 요청한다. 거부되면 ‘권한 꺼짐’을 표시하며 앱 사용을 막지 않는다. 저장된 시간·요일과 OS의 실제 전달 가능 상태를 별도로 표시한다. 일정 시각 보장·새 예보 확보를 문구로 약속하지 않는다. 알림 시 최신 추천을 확보하지 못하면 이전 예보 표시 또는 알림 생략 정책을 제공자·예약 방식과 함께 확정한다. 피드백 독촉 알림은 없다.

체감 보정 초기화: 직접 설정한 지역·패턴·민감도와 기록은 유지하되, 초기화 이전 기록의 보정 기여를 제외한다. 내 기록 삭제: 피드백 기록과 해당 보정 기여를 삭제한다. 아바타·장소 설정도 모두 삭제하는 기능과 혼동하지 않는다. 실제 로컬/동기화 저장 구조를 정한 뒤 범위 문구를 확정한다. 어느 삭제도 앱 시작 시 자동 실행하지 않는다.

캐시 사용 가능 기간은 공급자 조건·예보 대상 범위에 따라 결정하며 아직 숫자를 정하지 않았다. 대상 구간이 끝났거나 허용 기간을 넘은 자료로 새 추천을 표시하지 않는다. 자료 없는 상태에서 온도 0°·강수 0mm를 채우지 않는다. 실제 경보 지원 여부가 미확정이면 ‘경보 없음’으로 표시하지 않는다.

## 구현 전 검증 시나리오

1. 위치 권한 거부 → 수동 지역 검색 → H0 → 기본 추천/피드백까지 진입.
2. 두 지역·출발 시각 설정 → H2 → 출근/귀가 전환 → 지역·시점과 의류 상태 일치.
3. A1 대안 탐색 후 뒤로 → 기존 후보 유지. 확정 후 H 갱신, 실제 착장 기록은 없음.
4. 후보와 다르게 입음 → FA에서 재킷 휴대만 → 아바타 겉옷 없음 → 부모 유지 → 더움 상세.
5. 적당함 기록 시 착장·감각 미선택은 저장 막기. 선택 후 저장 성공 시만 FS.
6. 더움 상세 작성 → FW → 반영/취소 → 부모 입력 유지. ‘모름’과 다른 항목 동시 선택 불가.
7. 저장 연속 탭·실패·재시도 → 하나의 기록, 입력 유지. 수정/삭제 후 보정 중복 없음.
8. W2 집/직장 전환 → 모든 데이터와 지역 표시 동시 갱신. 한쪽 조회 실패 명시.
