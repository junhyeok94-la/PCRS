# 체감 피드백 화면 · 디자인 검토안

2026-11-02. 홈과 다른 차림의 승인된 시각 방향을 이어 [기본 피드백과 더웠던 상황 시안](../design/concepts/feedback-flow-v1.png)을 내장 Imagegen으로 생성했다. 이미지의 텍스트·데이터·선택 상태는 화면 검토용 예시다. 정적 이미지이며 입력·저장·개인 보정을 구현한 것은 아니다. 이 화면의 사용자 확인은 아직 남아 있다.

생성 프롬프트의 기준: 승인된 파란 배경·밝은 카드·3D 토이 인물을 유지하고, 두 화면에서 기본 체감 확인과 더움 상세의 차이를 보여준다. 날짜·시간·지역·예보 기준, 실제 착장 확인, 온열감·강도·상황, 선택형 예보 불일치를 분리한다. 필수 서술 입력을 넣지 않는다.

## 진입과 기본 피드백

홈 ‘입어보니 어땠나요?’에서 시작한다. 출근·귀가·다른 시간과 실제 경험 시각·지역을 확인·수정한다. 홈 조회 시각을 경험 시각으로 저장하지 않는다. 날짜 변경 지원 범위는 예보/추천 스냅샷 보존 범위와 함께 결정한다.

화면에는 해당 추천/후보 아바타와 의류 종류·두께를 보여주고 ‘이대로 입었어요’ 또는 ‘다르게 입었어요’를 명시적으로 선택하게 한다. 홈에서 후보를 고른 것을 실제 착용 확인으로 해석하지 않는다. ‘다르게 입었어요’는 상의·하의·겉옷의 종류/두께·없음/모름을 고치는 간단한 흐름으로 연결한다. 사진이나 보유 옷 등록을 요구하지 않는다. 겉옷을 챙긴 것과 해당 시점에 입은 것도 구분해야 한다.

몸의 느낌은 추웠어요·적당했어요·더웠어요 중 선택한다. 적당하고 착장이 확인되었다면 바로 기록할 수 있다. 실제 착장 미확인 상태는 일반 체감 기록으로 허용할지 검토하되, 추천의 성공 학습으로 사용하지 않는다.

**초기 상태에는 실제 착장, 몸의 느낌, 강도, 당시 상황을 미리 체크하지 않는다.** 시안에 체크된 적당함·동일 착장은 선택 후 상태의 예시다. ‘편안했다면 여기서 끝’은 선택 후 표시한다. 필수 항목 누락 시 항목 근처에 짧은 오류를 표시한다.

## 더움·추움 상세

기본 화면에서 더움 또는 추움을 선택한 경우 상세로 이동한다. 상단에는 경험 시점·지역·예보와 실제 착장 확인 상태를 요약하며 수정할 수 있다. 되돌아가도 입력을 유지한다.

강도는 조금·많이·매우를 사용하고 선택 시 행동 기준을 보여준다.

| 강도 | 더움 | 추움 |
|---|---|---|
| 조금 | 조금 덥지만 그대로 입을 만했어요 | 조금 춥지만 그대로 입을 만했어요 |
| 많이 | 겉옷을 벗거나 옷을 줄이고 싶었어요 | 옷을 더 입고 싶었어요 |
| 매우 | 이동을 멈추거나 빨리 식히고 싶었어요 | 빨리 따뜻한 곳으로 들어가고 싶었어요 |

이 표현은 사용자가 경험을 구분하기 위한 기준이며 의료적 단계나 검증된 온열감 척도로 주장하지 않는다. 모호한 표현은 사용성 확인 후 다듬는다. 아이콘과 색상만으로 강도를 구분하지 않는다. 생성 이미지의 ‘조금’ 파란 얼굴은 더움/추움 분류로 오인될 수 있어 구현 시 동일 계열 표시로 정리한다. 강도 카드의 ‘1/2’는 생성 과정의 장식으로 실제 화면에서는 제거한다.

주요 환경은 걷는 중·대중교통·실내·기타 중 선택하고, 경험이 여러 환경에 걸치면 시점을 나누어 기록하거나 주요 구간을 선택하도록 안내한다. 당시 상황의 후보는 땀·습하게 느낌·햇볕·바람·혼잡·비·젖음·냉방 등이며, 더움/추움에 관련된 항목을 우선 보여준다. 시안의 여섯 칩은 대표 예시로 최종 전체 목록이 아니다. 복수 선택을 지원하고 ‘특별히 없음’은 다른 선택과 동시에 고를 수 없게 한다. 선택하지 않은 상태와 없음을 구분한다.

## 예보와 다른 날씨 및 실제 의류 변경

‘예보와 날씨가 달랐나요?’는 선택 확장 영역이다. 개인 체감과 예보 불일치를 같은 답으로 취급하지 않는다. 펼치면 ‘비가 왔어요 / 비가 오지 않았어요 / 예상보다 바람이 셌어요 / 구름·햇볕이 달랐어요 / 잘 모르겠어요’ 등의 당시 예보와 비교 가능한 항목을 제안한다. 정확한 실제 기온·습도를 사용자가 측정했다고 가정하지 않는다. 이 목록은 후속 상세 화면 검토가 필요하다.

‘다르게 입었어요’의 실제 의류 변경 화면, 추움 상세, 예보 불일치 확장 상태와 기록 완료 상태는 이번 이미지에 포함하지 않았다. 추움 상세는 더움과 같은 구조를 재사용하되 문구와 상황 후보를 바꾼다. 실제 착장 수정과 예보 불일치의 상세 상태는 다음 디자인 범위다.

## 기록과 데이터 해석

기록에는 경험 시점·지역·추천/후보 스냅샷·실제 착장과 착용 확인 여부·감각 방향·강도·환경·선택 상황·예보 불일치 응답을 연결한다. 추천 당시 예보와 후속 갱신 자료를 덮어쓰지 않는다. 객관적 관측 자료가 있다면 출처·시각을 별도로 보관하며 주관적 느낌과 합치지 않는다.

저장 성공 전 성공 안내를 표시하지 않는다. 실패하면 작성 내용을 유지하고 다시 시도할 수 있게 한다. 완료 후 같은 경험의 중복 제출을 방지하고 수정 경로를 제공한다. 뒤로 가기는 입력을 보존한다. 별도 피드백 알림은 보내지 않는다.

한 번의 경험으로 모든 조건의 추천을 바꾸거나 즉시 정확도가 개선된다고 약속하지 않는다. 실제 효과·표본 기준·보정 범위는 검증 후 결정한다.

## 실제 차림 수정 시안

사용자가 기본·더움 피드백 시안에 동의한 후 [실제 입은 차림 수정 화면](../design/concepts/actual-outfit-v1.png)을 작성했다. 이 수정 화면은 아직 사용자 검토 전이다. 내장 Imagegen을 사용했으며 프롬프트는 승인된 색상·인물·카드 스타일을 유지하고, 실제 착용과 겉옷 휴대를 구분하는 한 화면을 표현하도록 지정했다.

상의·하의·겉옷 요약에서 항목을 선택하면 아래에 해당 종류와 두께 선택을 펼친다. 사진·브랜드·보유 옷 등록은 필요하지 않다. 미지원 의류와 모르는 두께를 임의의 값으로 보정하지 않으며, 대표 이미지로 표시하는 경우 세부 모양을 정확히 재현했다고 주장하지 않는다. 실제 의류가 이미지와 다르더라도 종류·두께 기준으로 답할 수 있어야 한다.

겉옷은 ‘입었어요 / 챙겨만 갔어요 / 없었어요’를 구분한다. 챙겨만 간 경우 아바타는 겉옷을 벗은 모습이며 해당 겉옷을 체감 시점의 착용 보온량에 포함하지 않는다. 없음을 선택하면 겉옷 종류·두께 입력을 숨기고 확정 초안에서 해당 값을 비운다. 상태를 다시 바꾸는 동안의 임시 선택은 복원할 수 있어야 한다. 시점 중간에 벗었다면 피드백이 어느 순간의 체감인지 시간·환경과 함께 구분한다.

종류·두께는 초기에는 추천/후보를 수정용 초안으로 불러올 수 있으나, 사용자가 ‘이 차림으로 확인’을 누르기 전 실제 착장 확인 완료로 취급하지 않는다. 화면의 체크는 변경 예시다. 확인 버튼은 피드백 초안을 갱신하고 부모 화면으로 돌아가며 최종 기록을 저장하지 않는다. 취소·뒤로 가기는 이 화면에서 확정하지 않은 수정을 버리고 부모의 기존 초안을 유지한다. 부모 피드백에서 고른 시간·온열감 등 다른 입력은 보존한다.

시안은 겉옷을 편집한 대표 상태다. 상의·하의의 종류/두께 목록과 모름 상태는 같은 틀로 상세 설계한다. 좁은 휴대폰에서는 네 개 두께 선택지를 줄 바꿈하며 글자를 줄이지 않는다. 생성 이미지에 축약된 ‘재킷 · 챙겨만 감’은 제품 문구 확정 시 ‘재킷 · 휴대’ 등 짧고 이해하기 쉬운 표현을 비교한다. 이 화면 역시 작동하는 프로토타입이나 분리된 의류 에셋은 아니다.
