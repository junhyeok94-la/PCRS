# 날씨 중심 UX 재구성 · v0.4 검토안

작성일: 2026-11-01. 사용자 의견: v0.3은 글이 많고 날씨 앱다운 시각적 전달이 부족함. 이 문서는 확정 디자인이나 앱 구현을 의미하지 않는다. Figma v0.3은 보존하며, 이번 비교안은 대화 내 미리보기로 검토한다. Figma MCP 호출 한도로 파일 수정은 진행하지 않았다.

## 벤치마킹 근거

실제 사용자 조사나 사용성 테스트 결과가 아닌 공식 안내의 화면·기능 구성에 대한 조사다. 운영체제·지역·버전에 따라 화면은 달라질 수 있다.

- [Apple 날씨 사용 설명서](https://support.apple.com/en-ie/guide/iphone/iph1ac0b35f/ios): 위치, 현재 기온, 최고·최저, 시간별, 여러 날 예보로 구성된다. 세부 기상 항목은 상세 보기로 확인한다. 적용 제안: 큰 현재 기온과 간결한 시간별 띠를 먼저 보여준다.
- [Samsung Galaxy 날씨 안내](https://www.samsung.com/us/support/answer/ANS10007276/): 현재 날씨와 시간별·주간 예보, 기온·강수 등의 정보를 제공한다. 공식 화면 자료의 아이콘과 수치 묶음을 참고한다. 적용 제안: 날씨 상태 아이콘·온도·강수확률을 시간별로 정렬한다.
- [Google Pixel Weather 안내](https://support.google.com/pixelphone/answer/15266029?hl=en): 상세 블록의 순서를 바꿀 수 있으나 요약과 시간별 예보보다 위로 이동할 수 없다. 위험 기상 경보는 요약보다 우선한다. 적용 제안: 상단의 정보 우선순위를 고정하고 설명·보조 지표는 아래 또는 상세로 이동한다. AI 요약 기능 자체를 첫 버전에 추가하는 결정은 아니다.

## 홈 재구성 제안

1. 현재 날씨: 지역, 큰 기온, 상태 아이콘과 짧은 명칭, 최고·최저. 체감온도는 보조 정보로 시험한다.
2. 오늘의 흐름: 시간, 아이콘, 기온, 강수확률. 출근·귀가를 같은 축에서 강조한다. 두 지역이 다른 맞춤 모드에서는 각 시점의 지역을 반드시 식별할 수 있어야 한다.
3. 오늘의 차림: 상의·하의·겉옷 세 칸과 탈착 안내 한 줄. 추천 이유는 펼쳐 본다. 현재 비교안의 하의 아이콘은 임시 기호이며 실제 UI에서는 알아보기 쉬운 의류 에셋으로 교체한다.
4. 관련 상황: 우산 등 행동이 필요한 안내만 짧게 표시한다. 경보는 옷 추천보다 앞에 표시한다.
5. 체감 피드백: 차림 영역에서 시작한다. 적당함과 실제 착장 확인으로 빠르게 끝내고, 더움·추움이면 강도와 당시 상황을 펼친다.

날씨 중심 배치와 착장 중심 배치를 비교한다. 추천 방향은 날씨 중심 배치다. 기본 날씨 확인과 우리 앱의 차별점인 옷 선택을 같은 흐름에 놓을 수 있다. 추가 지도·애니메이션·AI·다수 지표를 함께 도입하지 않는다.

## 글을 줄이는 원칙

- 문장을 작은 글씨로 축소하지 않는다. 핵심 수치·짧은 명칭·아이콘을 묶고 설명은 상세로 이동한다.
- 아이콘에 짧은 라벨을 붙인다. 색만으로 상태를 전달하지 않는다. 터치 영역은 약 44dp 이상 확보한다.
- 예보의 체감온도와 사용자의 더위·추위 민감도를 다른 개념으로 표시한다.
- 첫 추천은 지역 기본 추천이다. 설정을 하지 않은 사용자에게 출퇴근·도보·교통수단·민감도를 알고 있는 듯 표시하지 않는다.
- 예보 시각·갱신 실패·오래된 자료와 위험 경보는 숨기지 않는다.

## 피드백과 다음 설계 범위

대화 미리보기는 홈의 배치와 펼침 동작을 판단하기 위한 가상 날씨·착장 예시다. 실제 저장·예보 계산·개인 보정은 없다. 모든 탭과 상세 흐름이 구현된 프로토타입도 아니다.

강도는 조금·많이·매우와 행동 기준 설명을 함께 제공한다. 습하게 느낌·땀이 남 등은 주관적 경험으로 기록하며 실제 관측 습도로 해석하지 않는다. 실제 차림이 다르면 단순 의류 종류·두께 수정으로 연결한다.

후속 와이어프레임에서는 피드백의 날짜·시간·출근/귀가/기타·환경·착장 변경, 예보가 달랐다고 느낀 항목을 순서대로 펼치고 수정할 수 있게 설계한다. 미리보기에서 출근 시점을 고정한 것은 비교용 축약이며 최종 입력 흐름이 아니다. 정상 체감도 실제 착장이 확인된 경우에만 추천 보정 자료로 사용한다.

검토할 항목: 홈 배치 선택, 의류 그림의 식별성, 한 화면의 정보량, 두 지역 표시, 피드백 단계별 부담. 선택 후 시간별 화면·설정·예외 화면까지 같은 원칙으로 재구성한다. 기존 v0.3의 화면 수를 그대로 유지할 필요는 없다.

## 홈 하단 확장 · 사용자 검토 반영

사용자가 날씨 중심 배치를 선호하고, 오늘의 차림 아래로 스크롤하여 기타 날씨 정보도 보고 싶다고 제안했다. 홈은 현재 날씨 → 시간별 흐름 → 차림·피드백 → 상세 날씨 순서로 세로 스크롤한다. 실제 앱 하단 내비게이션은 화면에 유지하는 방향이며, 대화 미리보기는 내부 중첩 스크롤 없이 전체 내용을 펼쳐 보여준다.

상세 날씨는 두 열의 작은 카드로 습도·풍속/풍향·예상 강수량·자외선·일출·일몰을 제안한다. 짧은 명칭·큰 수치·단위를 기본으로 하고, 습도는 0~100% 눈금으로 표현한다. 강수확률과 예상 누적 강수량을 구분하고, 지역·현재/일별 기준을 식별할 수 있게 한다. 일몰과 귀가 시간의 관계는 저장된 귀가 시각이 있을 때만 표시한다.

카드의 숫자는 화면 비교용 가상 예시다. 데이터 제공자·갱신 주기·돌풍/UV/일출·일몰 지원은 미확정이다. 미세먼지는 별도 대기질 자료 연동을 검토한 후 결정한다. 제공되지 않는 수치는 0으로 대체하지 않는다. 작은 카드 내부의 세로 스크롤이나 긴 설명은 두지 않는다.
