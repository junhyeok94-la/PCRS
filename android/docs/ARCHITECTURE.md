# 앱 구조와 기존 서버 검토

최신 기술 검토: [제품 개발 검토](PRODUCT_TECH_REVIEW.md)와 [데이터 경계 초안](DEVELOPMENT_CONTRACTS.md)을 우선한다. 기존 서버의 가상 예보 폴백·개인화 수식을 그대로 사용하지 않고 독립 날씨 경계를 만들었다. 후속 [기상청 실제 연동](WEATHER_INTEGRATION_STATUS.md)과 로컬 HTTP 확인을 완료했으며 운영 배포는 하지 않았다.

기준일: 2026-10-30.

> 후속 제품 결정(2026-11-02): 대한민국 우선, 초기 옷장 보류, 3D 토이 스타일 선택. 실제 3D 엔진과 기존 서버 재사용은 미정입니다. 최신 [디자인 검토](DESIGN_REVIEW_V0_4.md)와 [개발 계획](DEVELOPMENT_PLAN_V0_4.md)을 우선하며, 아래 API 약관·가격 관련 이력은 공급자 선정 전에 다시 확인해야 합니다.

## 결정된 사항

- Android 우선. Kotlin과 Jetpack Compose로 독립 앱을 개발합니다.
- 기존 Next.js 화면·웹 배포 설정은 새 앱에서 사용하지 않습니다.
- 빈 앱 단계에서는 네트워크·인증·광고 의존성을 추가하지 않습니다.
- 기능별 패키지에서 시작하고 필요해질 때 데이터 계층을 추가합니다.

## 아직 결정하지 않은 사항

- 날씨 제공자와 서비스 지역
- FastAPI와 Supabase 재사용 여부
- 추천 계산을 앱에서 할지 서버에서 할지
- 계정·동기화 도입 시점
- 광고 형식과 배치

## 기능을 추가할 때 지킬 경계

화면은 ViewModel의 상태와 사용자 동작을 통해 데이터에 접근합니다. ViewModel은 공급자별 JSON이나 인증 SDK를 직접 다루지 않고 저장소 인터페이스를 사용합니다. 저장소 구현이 외부 응답을 앱의 데이터 모델로 변환합니다.

날씨 모델에는 단위, 시간대, 데이터 기준 시각, 갱신 시각, 출처를 명시합니다. 앱에 공급자 키나 서비스 관리자 키를 내장하지 않습니다. 비밀 키가 필요한 API는 서버를 경유합니다.

위치·날씨·추천은 비회원으로 먼저 사용할 수 있게 설계합니다. 개인화·옷장 기능은 로컬 저장부터 검토하며, 계정은 동기화 요구에 맞춰 도입합니다. 광고는 기능 화면과 분리된 통합 지점에 붙입니다.

## 기존 코드 검토 결과

| 기존 요소 | 확인한 구조 | Android에서의 판단 |
|---|---|---|
| Next.js 프런트 | Supabase SDK와 FastAPI에 연결된 4개 탭 | 사용하지 않음. 앱 화면 새로 구현 |
| FastAPI 추천 | 날씨 조회·UTCI·개인화·의류 조합·캐시가 `main.py`에 모여 있음 | 재사용 후보. 전체를 즉시 연결하기보다 날씨·계산·계정 경계를 먼저 분리할지 검토 |
| 날씨 어댑터 | Open-Meteo 예보·대기질, 좌표 캐시, 만료 캐시와 더미 예보 폴백 | 무료 API의 광고 앱 이용 조건 재검토 필요. 더미 예보 폴백은 새 앱의 실제 데이터 경로에 채택하지 않음 |
| Supabase 인증·DB | 토큰 검증, 사용자별 RLS 접근, 옷장·피드백·장소·탈퇴 데이터 | 선택 가능. Android 앱이나 광고 도입만으로 교체가 필수인 구성은 아님 |
| 사용자 데이터 | 기존 사용자·옷장·피드백과 DB 마이그레이션 | 재사용 결정 전에 실제 데이터·스키마 적용 상태 확인. 현재 작업에서 변경하지 않음 |
| Render·Vercel | 이전 웹 서비스 배포 설정 | 새 앱 빌드와 무관. 현재 작업에서 배포 변경하지 않음 |

재사용 후보라는 판단은 소스 구조 검토 결과입니다. 운영 서비스, DB 적용 상태, 계산 정확도, 모바일 인증 흐름은 이번 작업에서 검증하지 않았습니다.

## 광고와 API 선택

Android 앱 광고는 **Google AdMob**을 기준으로 검토합니다. 광고 SDK 도입과 날씨·추천 서버 선택은 각각 결정할 수 있습니다.

기존 Open-Meteo 무료 API는 비상업용입니다. 공식 약관은 광고를 표시하는 앱을 상업적 이용으로 명시합니다. 따라서 광고를 포함한 출시를 전제로 할 때 유료 상업용 플랜 또는 다른 제공자의 조건을 비교해야 합니다. 앱으로 전환하는 것 자체가 모든 API를 교체해야 하는 이유는 아닙니다.

날씨 제공자는 APP-02 시작 전에 아래를 기준으로 비교합니다.

- 목표 지역과 필요한 예보·자외선·대기질 항목
- 광고 앱의 상업적 이용, 재배포·캐시·출처 표시 조건
- 무료 할당량·비용·응답 지연·장애 처리
- 앱 직접 호출 가능 여부와 비밀 키 보관 방식

광고 구현은 APP-09에서 테스트 광고로 시작하고 필요한 동의 처리를 SDK 초기화·광고 요청 흐름과 연결합니다. 초기 앱에는 광고 SDK나 광고용 빈 영역을 넣지 않습니다.
