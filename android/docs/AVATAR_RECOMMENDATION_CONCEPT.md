# 아바타 기반 의상 추천 · 검토안

2026-11-02. 사용자가 의상 추천의 차별성 부족을 지적하고, 개인 아바타에 추천 의상을 입히는 방식을 제안했다. 본 문서는 확정 기능이나 개발 완료를 의미하지 않는다.

## 목표와 홈 구성

추천 의류의 종류·두께와 시간대별 겉옷 탈착을 내 아바타로 이해하고, 외형을 꾸미는 애착을 더한다. 추천 품질은 기상·민감도·생활 패턴·검증된 피드백으로 개선해야 한다. 아바타 외형을 정확한 신체 체형이나 보온 성능으로 해석하지 않는다.

홈 비교안 두 가지: ‘날씨와 함께’는 현재 날씨 → 시간별 → 아바타 추천 → 상세 날씨 순서, ‘아바타 중심’은 현재 날씨 → 아바타 추천 → 시간별 → 상세 날씨 순서다. 사용자가 앞서 선호한 날씨 중심 구성을 존중해 첫 안을 기본 비교안으로 둔다. Figma에는 아직 반영하지 않았다.

## 추천 영역의 핵심 동작

- 출근·귀가 선택: 같은 하루 추천에서 해당 시각의 겉옷 착용 상태를 보여준다. 가져갈 겉옷과 지금 입을 겉옷을 구분한다. 두 지역일 경우 실제 지역을 각각 표시해야 한다.
- 다른 차림 보기: 날씨와 개인 조건에 적합한 상의·하의·겉옷의 대안을 비교한다. 옷 색만 바꾸는 기능으로 정의하지 않는다. 현 미리보기는 긴팔+재킷과 긴팔 니트+가디건 예시다. 소재·두께와 추천 계산은 후속 검증한다.
- 차림 선택: 오늘 입을 후보를 정한다. 실제 착용으로 자동 기록하지 않는다.
- 내 아바타 꾸미기: 헤어·피부 톤 등 외형을 선택한다. 첫 실행에서 강제하지 않고 기본 아바타로 시작한다. 외형 변경은 추천 기준을 임의로 바꾸지 않는다.
- 입어본 뒤 피드백: 실제 착장을 확인하고, 적당하면 간단히 마무리한다. 더움·추움은 강도·상황을 추가한다. 기존 구조화된 피드백 요구를 유지한다.

## 첫 버전 후보와 미정 사항

단순한 2D 몸체에 상의·하의·겉옷을 순서대로 겹치는 방식이 후보이며 3D·사진 기반 가상 착용·핏 재현·개인 옷장 자동 인식은 포함하지 않는다. 중립적인 기본 체형, 머리·의류 간 겹침, 체형 확장 여부, 에셋 제작과 조합 수, 접근성 설명을 상세 디자인에서 결정한다. 현재 그림은 대화 비교용 임시 코드 일러스트다.

현재 미리보기는 가상 날씨·프로필을 사용한다. 지역·출근 시각·이동 패턴 등이 없으면 기본 추천으로 명확히 표시하고 미설정 정보를 개인화한 것처럼 표현하지 않는다. 차림 선택·피드백은 실제 서버 저장·개인 보정을 수행하지 않으며, 피드백의 후속 단계는 기존 설계에 연결할 예정이다.

검토할 사항: 추천 영역의 위치와 크기, 아바타 그림체·비율, 겉옷을 챙긴다는 표현, 대안 선택의 실효성, 초기 꾸미기 항목, 추천과 꾸미기의 관계. 의류에 의미 있는 차이가 보이도록 종류·두께의 짧은 명칭을 반드시 병기한다.

## 시각 방향 선택과 다른 차림 화면

사용자가 3D 토이 스타일을 선택하고, 해당 캐릭터를 넣은 홈 디자인 시안에 긍정적으로 동의했다. [홈 시안](../design/concepts/home-toy-v1.png)을 시각적 기준으로 사용한다. 실제 3D 엔진을 사용하는 것으로 확정한 것은 아니다. 완성된 렌더 이미지 방식도 후보로 남긴다. 기존 코드 기반 임시 아바타는 최종 품질 기준이 아니다.

사용자의 진행 요청에 따라 [다른 차림 화면 시안](../design/concepts/outfit-alternatives-v1.png)을 생성했다. 이 화면은 새 검토안이며 아직 사용자 확인 전이다. 홈의 ‘다른 차림’ → 비교 화면 → 후보 선택 → 홈의 차림 갱신 흐름을 제안한다. 뒤로 가면 선택 확정 전의 홈 차림을 유지한다.

- 동일 인물·자세로 겹쳐 입기(긴팔+재킷), 한 장으로(니트), 가디건 조합(반팔+가디건)을 비교한다. 색상 차이만으로 대안을 만들지 않는다.
- 선택 카드는 체크 표시와 배경으로 구분하고, 아래 상세 영역을 해당 조합의 의류 종류·두께와 출근·귀가 대응법으로 갱신한다.
- ‘이 차림을 오늘의 후보로’는 후보 선택이다. 실제 착용·체감 피드백 저장이나 추천 학습을 자동으로 수행하지 않는다.
- 대안 수는 적합한 조합이 있을 때 최대 3개를 제안하며, 세 칸을 채우려고 부적합한 옷을 생성하지 않는다. 현재 수치와 조합은 시각 검토용 예시이며 적합성 검증을 통과한 추천 결과가 아니다.
- 좁은 기기에서 3열 비교의 캐릭터·글자 식별성을 확인한다. 필요하면 두 열 또는 가로 선택 방식으로 상세 설계한다. 글자를 축소해 맞추지 않는다.

두 시안은 내장 Imagegen으로 생성한 래스터 디자인 이미지다. 버튼·선택 변경·저장 기능이 작동하는 프로토타입이나 분리된 의류 에셋이 아니다. Figma 반영과 실제 에셋 제작, 초소형 화면 검수는 남아 있다. 생성 프롬프트의 공통 기준은 승인된 홈의 파란 날씨 배경·밝은 카드·3D 토이 인물 정체성을 유지하고, 실용적인 조합 세 가지와 선택 상세·후보 확정 동작을 표현하는 것이었다.

### 대안 선택 v2: 큰 아바타와 작은 미리보기

사용자가 작은 아바타 세 개를 동등하게 배치하는 대신 큰 아바타 하나·작은 대안 미리보기·선택 이유 한 줄로 수정하는 데 동의했다. [수정 시안](../design/concepts/outfit-alternatives-v2.png)은 이 방향으로 내장 Imagegen을 사용해 생성했다. v1은 비교용으로 보존한다.

상단의 큰 아바타와 의류 정보는 현재 탐색 중인 대안이다. 좌우 이동 또는 작은 미리보기 선택 시 아바타·종류/두께·출근/귀가 대응법·선택 이유·현재 순서를 함께 갱신한다. 좌우 스와이프 외에 버튼으로도 조작할 수 있게 한다. 적합한 대안이 하나라면 이동 버튼과 순서를 표시하지 않는다. 후보 변경은 하단 ‘오늘 이 차림으로’를 눌렀을 때만 확정하고, 확정 전 뒤로 가면 기존 후보를 유지한다.

선택 이유는 옷 이름의 반복 대신 조절 가능성·겉옷 휴대 부담·실내 탈착 등 실제 차이를 설명한다. 민감도나 이동 패턴이 미설정이면 해당 개인 정보를 알고 있는 것처럼 표현하지 않는다. 기본 추천 표시와 입력된 조건을 구분한다.

프롬프트 기준: 승인된 인물과 홈의 디자인을 보존하고, 큰 전신 아바타 하나와 작은 대안 세 개, 짧은 선택 이유, 의류 세 항목, 시간대별 안내와 짧은 확정 버튼을 표현했다. 생성 결과는 정적인 검토 이미지이며 실제 모바일에서 첫 화면의 대안 발견성과 스크롤 길이를 확인해야 한다. 남은 피드백 상세 화면을 이 시안에 구현한 것은 아니다.

사용자가 v2 방향에 동의했다. 후속 [피드백 화면 설계](FEEDBACK_FLOW_DESIGN.md)에서는 실제 입은 차림과 당시 체감을 확인하고, 더움·추움에만 상세 입력을 연결한다. 기본·더움 상태의 이미지 시안은 작성했으며 실제 의류 변경 등 후속 상태는 아직 디자인 검토가 필요하다.
