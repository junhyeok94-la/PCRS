# 날씨 연동 1단계 확인

캐시 후속 변경: [앱·서버 영속 캐시와 일일 요청 관리](CACHE_IMPLEMENTATION_STATUS.md)를 추가했다. 아래 메모리 전용·TTL 설명은 서버 1단계 당시 기록이다.

후속 진행: [Android 지역 기본 홈](HOME_IMPLEMENTATION_STATUS.md)에 실제 지역 검색·저장·홈·시간별 표시를 연결했다. 아래 내용은 서버 1단계의 검증 기록이다.

2026-11-02. 사용자가 로컬 `.env`에 키를 직접 설정했고, 키나 상류 인증 URL을 출력하지 않고 검증했다. 인증키·원본 가이드·실조회 결과는 Git에서 제외한다.

## 완료한 것

- 기존 웹·Supabase와 독립된 [날씨 서비스](../../weather_api/README.md) 구현.
- 최신 공식 가이드·행정구역 XLSX로 전국 3,839개 지역 검색. 구/동의 전체 경로와 격자를 유지하고 같은 이름을 구분함.
- 실황과 예보를 서로 다른 자료 종류·발표/수신 시각으로 정규화. °C·m/s·%·mm, 누락/null과 0, 범주형 강수량 구분.
- 실제 마포구·강남구에서 각각 36시간 예보·1개 실황을 정상 수신. 두 지역 모두 `available`, `fresh`, `isSample=false` 확인.
- 반복 요청에서 같은 수신 시각·캐시 재사용 확인. 실제 로컬 HTTP의 지역 검색·두 지역 날씨 응답도 확인.
- 27개 자동 테스트: 날짜/발표 경계, UTC→KST, 페이지 나눔, 잘못된 격자, XML 인증 오류, 누락값, 실황 강수/예보 범주 구분, 일최저/최고 누락, 부분/전체 실패, 캐시 만료·지연, 요청 합치기·한도 등 통과.
- [.env 예제](../../weather_api/.env.example), [OpenAPI 계약](../../weather_api/openapi.json), 명시적 실조회 명령, 실행 방법 기록.

현재 PC에서 서버는 `http://127.0.0.1:8010`으로 실행했다. [API 문서](http://127.0.0.1:8010/docs)를 열면 요청을 확인할 수 있다. 로컬 프로세스의 계속 실행이나 PC 재부팅 후 자동 시작을 보장하지 않는다. 프로세스·로그는 `weather_api/.cache/`에만 기록한다.

## 서버 1단계 당시 후속 범위

- Android의 네트워크 클라이언트·지역 저장·홈/시간별 실제 화면: 후속 작업에서 구현했다. 맨 위 링크 참고.
- UV·일출/일몰·대기질·체감온도·위험 기상 경보.
- 의상 추천·개인 보정·피드백 DB·알림.
- 외부 서버 배포·운영 HTTPS·다중 인스턴스 캐시/전역 한도.

이번 작업은 서버 경계와 실제 기상청 연동의 1단계다. Android 빌드를 변경하지 않았으므로 앱 빌드/lint를 다시 실행하지 않았다. 기존 디버그 아바타 검증 이력과 구분한다. 이 문단은 서버 1단계 당시의 기록이며, 현재 Android 연결 상태는 맨 위 후속 진행 문서를 따른다.

## 다음 개발 단위

승인된 홈 디자인을 Compose로 옮기면서 이 API의 지역 검색·실황·예보를 연결한다. 처음에는 지역 기본 홈을 먼저 완성하고, 출퇴근 설정과 추천은 뒤에 붙인다. 설정 전 도보·민감도를 아는 것처럼 표시하지 않는다. 앱에서 외부 인증키를 갖지 않으며 에뮬레이터는 호스트 PC의 `10.0.2.2:8010`에 접근하는 디버그 구성을 사용한다. 운영 API 주소/HTTPS와 구분한다.
