# 출퇴근·선택 민감도 구현

M5: 집과 직장·학교의 출발 지역·시각, 다음 날 귀가, 선택 요일, 독립적인 추위/더위 성향, 도보·이동 수단·실내 환경을 앱에 연결했다. 첫 실행은 기존처럼 지역 하나로 시작한다. 개인 성향 입력은 설정에서 선택적으로 추가한다.

## 화면과 저장

- 설정 → 출퇴근 / 더위·추위 / 이동·실내 환경. 자식 화면에는 하단 탭을 숨긴다. 취소·Back은 저장 전 초안을 버리고 원래 화면으로 돌아간다. 지역 선택의 Back은 출퇴근 편집 화면으로 돌아가며 편집 중인 다른 값을 유지한다.
- 지역 선택은 공식 행정구역 검색을 재사용한다. 출퇴근 지역을 고르는 동안 기존 날씨 기준 지역을 덮어쓰지 않는다. 시각은 HH:mm, 이동 출발 시각이며 도착 시각이나 경로는 추정하지 않는다.
- 귀가 출발이 출근보다 이르거나 같으면 ‘다음 날’ 선택이 필요하다. 같은 지역 두 번 선택은 허용한다.
- 요일 미설정은 null로 보존한다. 이 경우 모든 날짜를 후보로 다음 일정을 표시하며 화면에 ‘요일 미설정’을 명시한다. 선택한 요일은 출근 출발일 기준이다. 금요일 출근 후 토요일 새벽 귀가도 금요일 일정이다.
- 추위/더위는 각각 미설정·덜 타요·보통·많이 타요를 구분한다. 두 값이 모두 높을 수 있다. 미설정을 보통으로 저장하지 않는다.
- 도보 없음/10분 이내/10~30분/30분 이상, 이동 수단, 서늘한 실내/더운 실내/일정하지 않음을 선택적으로 저장한다. 도보 이동과 도보 없음이 함께 선택되면 확인을 요청한다.
- 별도 DataStore `personal_settings`, profile v1에 원자적으로 저장한다. 저장 실패 시 완료 화면으로 이동하지 않는다. 미지원/손상된 저장 형식은 읽기 오류로 표시하며 자동으로 빈 프로필을 덮어쓰지 않는다.

## 날짜와 예보

앱의 대한민국 시간대를 사용한다. 현재 진행 중이거나 다음에 돌아오는 출퇴근 일정을 찾아 실제 날짜·지역·출발 시각을 표시한다. 지난 출근은 ‘시각 지남’으로 표시하고 귀가를 확인할 수 있다. 귀가까지 지나면 다음 후보 일정으로 전환한다.

출발 시각의 정시 예보를 사용한다. 예를 들어 08:30 출발에는 08:00 예보를 사용하고 두 시각을 별도로 표시한다. 해당 정시가 없으면 추천 불가로 표시한다. 몇 시간 뒤의 자료나 관측으로 임의 대체하지 않는다. 선택 요일의 다음 일정이 예보 범위를 넘으면 예보가 없다고 표시한다.

홈은 기존 날씨 → 시간별 흐름 → 출퇴근 차림 → 상세 날씨 순서를 유지한다. 출근/귀가 전환마다 지역·날짜·예보 시각·차림이 함께 바뀐다. 상의와 하의가 같을 때에는 공통 기본 차림과 시간별 겉옷 입기/휴대를 연결한다. 한 시각에 필요한 겉옷은 다른 시각에 챙길 수 있게 표시한다. 상의·하의 구성 자체가 달라지는 경우에는 시각별 차림을 제공한다. 모든 기온 차이에 대해 하나의 종일 착장을 최적화한 것은 아니다.

시간별 탭은 기준 지역/집/직장·학교를 구분해 각각 한 지역의 그래프를 제공한다. 서로 다른 지역의 기온을 한 선으로 이어 붙이지 않는다.

## 성향 규칙 preference-0.1

기본 regional-0.1 위에 적용하는 **직접 설정 기반 초기 휴리스틱**이다. 기존 웹 UTCI 보정식·나이/성별/체지방 계수는 이식하지 않았다. 기상 기온을 바꾸거나 검증된 개인 체감온도를 산출하지 않는다.

| 조건 | 동작 |
|---|---|
| 추위 많이·17~20℃ 미만 | 기본 휴대 재킷을 착용으로 제안 |
| 추위 많이·12~17℃ 미만 | 니트·중간 재킷 구성 |
| 추위 많이·9~12℃ 미만 | 니트·보온 바지·코트 구성 |
| 추위 많이·5~9℃ 미만 | 내의·니트·보온 바지·패딩 구성 |
| 추위 많이·5℃ 미만 | 기본의 높은 보온 구성 유지 |
| 추위 덜·12~17℃ 미만 | 겉옷 휴대 제안 |
| 추위 덜·17~20℃ 미만 | 겉옷 없음. 바람 보호가 필요하면 휴대 유지 |
| 더위 많이·20~23℃ 미만 | 얇은 반팔·얇은 긴바지 |
| 더위 많이·17~20℃ 미만 + 명시한 도보 | 입기보다 휴대·탈착 우선. 추위 높음도 다른 서늘한 시간대에 별도 적용 |
| 실내 서늘함·20℃ 이상 | 외출 차림 위에 얇은 재킷을 챙기는 구성 |

보통과 미설정은 기본 규칙을 유지한다. 더위를 덜 타는 설정은 추가 경량화를 적용하지 않는다. 도보·자전거·실내 더움은 조절 안내로도 반영한다. 모든 선택이 모든 날씨에서 다른 옷을 만드는 것은 아니다. 바람·강수 안내는 별도로 유지하며 아직 실제 체감 학습은 없다.

상의·하의·겉옷·입기/휴대가 일치하는 경우에만 기존 8종 이미지를 연결한다. 얇은 긴바지 차림에서 재킷을 챙길 때에도 겉옷을 벗은 정확한 기본 이미지를 사용한다. 지원 조합은 216개 가능한 조합 중 12개이며 미지원 조합의 대체 표현은 유지한다.

## 자원·정보 경계

민감도·도보·실내 정보·출발 시각은 앱에서 사용하고 날씨 서버에 전송하지 않는다. 서버에는 지역 ID와 조회 범위만 요청한다. API 키·생년월일·신체 정보·계정·광고 SDK는 새로 추가하지 않았다.

두 지역이 모두 필요할 때 한 HTTP 요청으로 묶고, 이미 유효한 지역 캐시는 요청에서 제외한다. 같은 지역이면 중복을 제거한다. 성향만 바꾸면 날씨 재수집 없이 추천을 재계산한다. 시간별에서 아직 읽지 않은 장소는 선택할 때 캐시부터 확인한다. 앱이 배경에 있을 때 새 출퇴근 일정을 폴링하는 작업은 추가하지 않았다.

## 검증과 다음 단계

앱 테스트 61개와 디버그·릴리스 빌드·lint를 확인했다. 선택 성향 조합의 의류/아바타 일치, 미설정 보존, 자정·요일·정확한 예보 시각·과거/누락, 두 지역 일괄 요청·부분 응답·캐시 재사용을 포함한다. 실제 앱의 저장·취소·재실행·작은 화면 검증은 [검증 화면](../design/personal-validation/README.md)에 기록한다.

다음은 M6 구조화 피드백이다. 실제 입은 차림과 휴대, 더움/추움·강도·상황·예보 불일치를 구분한 기록을 만든 뒤 추천 효과를 평가한다. 신체 정보의 기여·자동 개인 보정·알림·운세는 아직 구현하지 않았다.
