## 이동과 복귀

- 첫 실행: I1 → H0. 출퇴근 설정은 H0에서 원할 때 C1 → H2.
- 기본 상태 하단 탭: H0 / W0 / S0. 출퇴근 상태 하단 탭: H2 / W2 / S2.
- 추천 이유: H0 → R0, H2 → R2. 각각 원래 추천 상태로 복귀.
- 피드백: H0 또는 H2 위에 F1을 전체 화면 오버레이로 열고, FH·FC·FA·F3로 오버레이 화면을 교체. 완료·취소 시 오버레이를 닫아 원래 추천 화면 유지.
- 상세 피드백에서 이전은 간단 평가로 돌아가는 예시 경로. 실제 앱에서는 입력한 내용을 유지하도록 설계해야 함.
- 선택 설정 P1·M1·N1은 저장 후 진입한 화면으로 복귀. 출퇴근 설정 C1은 ‘저장하고 추천 보기’로 H2에 진입.
- 초기화 확인 D1은 확인·취소 후 설정으로 복귀. 프로토타입에서는 실제 데이터가 바뀌지 않음.
- 조회 실패 E1은 별도 검토 시작점으로 제공한 지역 기준 실패 예시. 재시도는 H0, 지역 확인은 S0으로 이동. 실제 앱에서의 출퇴근 상태 오류·재시도도 저장한 설정을 보존해야 함.

## 입력 부담과 피드백 기준

처음에는 지역만 선택합니다. 시간별 날씨·추천 이유·피드백을 위해 출퇴근 설정을 강제하지 않습니다. 민감도·신체 정보·이동 상세는 각각 필요할 때 편집합니다.

피드백의 시각·상황은 사용자가 확인할 수 있어야 합니다. 적당함의 빠른 완료는 추천대로 실제 착용한 경우에만 사용합니다. 더움·추움 강도는 조금 / 많이 / 매우와 설명을 제시합니다. 당시 상황은 여러 개 선택할 수 있고 기억나지 않으면 생략할 수 있습니다. 실제로 바꿔 입은 의류는 전체 옷장 없이 종류·두께로 기록합니다.

주관적 체감·환경 보고와 기상 관측값은 구분합니다. 추천 당시 예보는 피드백 맥락으로 표시하되 실제 관측 자료라고 표현하지 않습니다. 외출 후 불편함을 기록한 결과가 어떤 조건에 반영되는지는 계산 명세와 검증이 필요합니다.

## 데이터 제어의 의도

체감 보정 초기화는 직접 설정한 위치·시각·민감도를 지우는 기능과 구분합니다. 이전 피드백을 기록으로 유지할 경우에도 초기화 이전 기록을 다시 누적해 보정을 자동 복원하지 않도록 해야 합니다. 삭제·보존 범위와 초기화 기준 시각은 개발 명세에서 확정합니다.

## 검수 상태와 남은 정리

생성 응답에서 편집 가능한 텍스트 338개·인스턴스 150개, Noto Sans KR 사용, 전체 UI 래스터 이미지 미사용을 확인했습니다. 화면 이동 컨트롤은 단일 동작으로 구성했습니다. Figma 플랜에서 복합 프로토타입 동작이 제한되어, 피드백은 오버레이 교체·닫기로 원래 추천 상태를 보존하도록 구성했습니다.

최종 MCP 재검수 호출은 Starter 플랜의 도구 호출 한도로 실행되지 않았습니다. 따라서 마지막 문구 수정과 전 화면의 재읽기 검수가 모두 끝났다고 판단하지 않습니다. 브라우저의 읽기 전용 캔버스로 추천·시간별·피드백·설정·알림·예외 상태 배치를 확인했습니다. 프로토타입 재생은 브라우저의 Figma 로그인 화면에 막혀 전체 클릭·스크롤 동작을 검증하지 못했습니다. 다음 항목은 후속 정리 대상입니다.

- N1의 ‘알림 권한이 꺼진 경우 보기’를 제품 문구인 ‘알림 권한 확인’으로 정리.
- E1의 ‘다시 시도 · 성공 예시’에서 경로 검토용 표현을 제거해 ‘다시 시도’로 정리.
- D1의 기록·보정 초기화 차이를 위 데이터 제어 의도에 맞춰 문구 정리.
- 내비게이션의 라이브러리 기본 아이콘을 실제 목적에 맞는 아이콘으로 교체하는 작업은 UI 디자인 단계에서 진행.
- 장소 검색 결과·입력 검증·날씨 갱신 중·오래된 자료 표시와 피드백 수정·중복 입력은 상세 상태 설계에서 보완.
- 실제 입력값 반영, 전체 터치 경로와 취소·복귀·스크롤 동작의 사용성 검증은 별도로 진행.
