# 제품 기획 인터뷰

기준일: 2026-11-01. 사용자와의 질문·답변을 바탕으로 작성하는 기획 초안입니다. 확정한 요구와 제안·가설을 구분합니다.

현재 구상을 묶은 [제품 기능 범위와 화면 구성](PRODUCT_SCOPE_AND_SCREENS.md) 및 Figma 와이어프레임을 작성했습니다. 최신 v0.3은 지역만 선택하는 시작 흐름을 유지하고 [다른 화면과 예외 상태](SCREEN_FLOW_V0_3.md)를 확장한 초안입니다. 인터뷰 기록은 이 문서에 유지하며, 화면·첫 버전 범위는 별도 초안에서 함께 검토합니다.

## 진행 원칙

제품 기획, 화면 구조, 와이어프레임, UI 디자인·프로토타입, 개발 명세를 먼저 정리한 후 기능 개발을 시작합니다. 기존 빈 앱과 개발 계획의 기능 순서는 최종 제품 범위를 확정한 것으로 취급하지 않습니다.

## 확인된 사용자 요구

- Android 우선 개발.
- 첫 대상: 출근·등교 전에 입을 옷과 준비물을 결정하는 사람.
- 기존 날씨 앱에서 기온을 알아도 본인이 어떻게 입어야 하는지 판단하기 어려움.
- 실제 사례: 기온 19도에 골덴 블레이저를 걸쳤으나 걷다 보니 예상보다 더웠음.
- 평소 출근 이동: 대중교통까지 도보 약 5~10분, 주로 지하철 이용, 도착 후 사무실 내근.
- 아침 입력 부담: 평소 출근 패턴을 한 번 설정하고 매일 바로 추천받기를 선호.
- 아침 추천의 시간 범위: 출근할 때와 퇴근·귀가할 때를 모두 고려.
- 원하는 결과: 상의·하의·겉옷을 포함한 기본 차림 전체. 겉옷 한 가지 안내만으로 범위를 제한하지 않음.
- 최초 개인화: 더위·추위 민감도와 생활 패턴을 입력하고, 키·몸무게 등 신체 정보는 선택 입력으로 제공.
- 첫 서비스 지역: 대한민국 우선.
- 기준 위치: 집과 직장·학교 위치를 처음에 저장.
- 피드백은 자유 서술 중심이 아니라 선택 목록을 사용. 적절한 차림이었다면 간단히 완료하고, 불편했다면 당시 시간대·기상 상황·습함·땀 등 상황과 더위·추위 강도를 구체적으로 선택할 수 있어야 함.
- 피드백 진입: 필요할 때 홈의 오늘 추천에서 사용자가 직접 입력. 피드백 요청 알림은 사용하지 않음. 아침 복장 추천 알림과는 별개의 결정.
- 사용자가 질문에 답하는 방식으로 기획을 진행하기를 원함.
- v0.1 와이어프레임 검토 의견: 첫 실행 후 입력량이 너무 많음.

## 초기 입력량 개선 — v0.2 변경 제안

지역 한 곳만 고르고 기본 추천을 먼저 경험한 뒤, 원하는 경우 두 장소·출퇴근 시각을 설정하는 방식으로 와이어프레임을 수정했습니다. 이동 상세·민감도는 이후 조정, 선택 신체 정보·아침 알림은 사용자가 원할 때 입력합니다. 개인화 전 결과는 지역 기준 기본 추천으로 구분합니다. 최초 설정 전체를 완료해야 추천을 볼 수 있는 v0.1 방식은 최신 검토안에서 대체합니다.

두 장소를 저장해 출퇴근 추천을 받으려는 목적은 유지하며 입력 시점을 늦추는 제안입니다. 사용자의 화면 검토 후 최종 확정합니다.

## 사용자가 제안한 기능 후보

- 출근 준비를 위해 사용자가 정한 기상 시각에 오늘의 복장 추천 알림을 받음.
- 알림의 첫 버전 포함 여부, 시간·요일, 표시 내용과 지연·날씨 갱신 실패 시 동작은 아직 확정하지 않음.

## 현재 제품 가설 — 미확정

핵심 질문은 ‘오늘 출근·등교할 때 나는 어떻게 입으면 좋을까?’로 둡니다.

기온뿐 아니라 이동 중 활동, 실내외 환경, 사용자의 이전 체감 피드백을 연결하면 착장 판단을 도울 수 있다는 가설입니다. 위 사례만으로 더웠던 원인을 걷기나 의류 한 가지로 단정하지 않습니다.

구현 후보:

- 한 번 설정한 이동 패턴으로 아침에 겉옷·레이어 수준을 바로 확인. 당일 일정 입력은 필수로 요구하지 않음.
- 알림에서 복장 요약과 준비물을 확인하고 앱에서 추천 이유와 시간대별 차이를 확인.
- 개인 옷장을 도입할 경우 미리 등록한 겉옷에서 추천. 매일 후보를 골라야 하는 흐름은 기본 경로로 두지 않음.
- 외출 후 ‘더웠음 / 적당함 / 추웠음’을 기록하고 비슷한 조건의 추천을 점진적으로 보정.

전체 옷장 등록, 신체 수치 입력, 사진 인식, 로그인은 이 흐름의 필수 조건으로 아직 확정하지 않았습니다. 정확한 체감 예측이나 추천 성능도 검증 전입니다.

## 답변 대기

현재 발송된 인터뷰 질문 중 답변 대기 항목 없음. 다음 검토 대상은 첫 버전 범위·홈 화면 정보 우선순위와 상세 피드백 항목.

## 구조화된 체감 피드백 — 상세 설계 초안

사용자 요구: 적절한 추천은 간단히 완료, 불편한 추천은 상황과 강도를 선택식으로 구체화. 자유 서술은 첫 버전의 필수 입력이나 개인화 판단 근거로 두지 않음.

아래의 단계·항목·척도는 요구를 구체화한 제안이며, 와이어프레임 검토 전 최종 확정 아님.

1. 홈의 오늘 추천에서 실제 착용 후 평가에 진입. ‘추천대로 입었고 적당했어요’를 선택하면 빠르게 완료하는 방안 검토. 추천을 읽고 확인한 것과 실제 착용 결과를 혼동하지 않게 표현.
2. 불편했다면 ‘조금 / 많이 / 매우’ 등 강도를 추가 선택. 7단계 후보: 매우 추움, 많이 추움, 조금 추움, 적당함, 조금 더움, 많이 더움, 매우 더움. 각 문구에 사용자가 구분할 수 있는 설명을 붙이는 것을 검토. 객관적인 신체 온도 측정치로 해석하지 않음.
3. 대상 시간대와 구간 선택. 출근·귀가, 실제 경험 시각, 걷는 중·대중교통·실내 등. 최초 생활 패턴을 기본값으로 제시하되 변경 가능하게 설계.
4. 당시 상황을 선택 목록으로 제공. 예: 땀이 남, 공기가 후텁지근하게 느껴짐, 햇볕이 강함, 바람이 강함, 비를 맞음, 지하철 안이 더움, 실내 냉방이 강함. 실제 목록과 복수 선택 여부·필수 여부는 화면에서 검토. 선택한 상황은 경험 보고이며 원인 확정값이 아님.
5. 실제 착장이 추천과 같았는지 확인. 다르면 상의·하의·겉옷 중 바뀐 부분을 간단히 기록하는 방안 검토. 개인 옷장 전체 등록을 전제로 하지 않음.

### 데이터 해석과 개선 방향

- ‘추천을 확인/수락함’과 ‘실제 입고 활동한 뒤 편안했음’을 별도 사건으로 구분. 화면에서 확인만 한 OK를 체감 피드백으로 학습하지 않음.
- 추천 생성 당시의 예보, 추천 대상 시간대·위치, 추천한 옷의 범주, 추천 규칙 버전과 피드백을 연결하는 방안 검토.
- 예보와 실제 날씨의 차이, 개인의 주관적인 체감, 착장 변경을 구분. 사용자가 ‘습했다’고 선택했다고 관측 습도 수치를 바꾸거나 예보 오류로 확정하지 않음. 해당 시간대 관측 자료를 제공자가 지원하면 비교 가능성을 검토.
- 걷는 중 더웠다는 피드백은 해당 활동·환경과 비슷한 조건의 추천 보정 후보로 사용. 지하철 안에서 더웠다는 경험을 모든 야외 조건의 보온 수준에 그대로 적용하지 않음.
- 한 번의 강한 피드백으로 추천 전체를 크게 바꾸지 않는 제한된 규칙 보정부터 검토. 개인화 개선 효과는 별도 검증.

첫 화면에는 간단한 평가만 두고, 불편을 선택한 경우에 상세 질문을 펼쳐 평소 입력 부담을 줄이는 방안을 검토.

## 옷장 기능 검토 — 결정 보류

사용자는 의류 등록 화면의 구현 난이도와 실제 효용이 만족스러울지 우려함. 개인 옷장 도입을 확정하거나 거절한 상태는 아님.

검토 관점:

- 등록·수정·삭제 UI와, 옷의 속성을 이용한 추천 품질은 별개의 과제.
- 이름이나 사진만으로 보온성·착용감을 정확히 판단한다는 전제는 두지 않음.
- 수동 등록을 도입한다면 종류·두께 등 최소 입력으로 시작하고, 입력 수고에 비해 추천이 얼마나 구체화되는지 확인해야 함.

단계별 대안(제안, 미확정): 첫 버전은 의류 종류·두께·레이어 수준을 추천하고, 다음에 개인 겉옷 몇 개를 선택 등록하는 방식을 검토. 전체 옷장과 사진 인식은 핵심 사용 흐름을 검증한 뒤 판단.

## 기본 추천 화면의 방향 — 와이어프레임 후보

상의·하의·겉옷을 각각 종류·두께 수준으로 표시하고, 출근과 귀가 조건이 다르면 겹쳐 입거나 벗는 방법을 설명하는 흐름을 검토. 우산 등 준비물은 기상 조건에 따라 별도로 표시할 후보. 기온·이동 패턴·실내 환경·개인 보정 중 추천에 영향을 준 이유를 짧게 제공.

와이어프레임은 옷 등록 없이 사용할 수 있는 경로부터 설계하고 개인 옷장 기능은 보류함. 실제 보유 의류 자동 선택이나 스타일·색상 조합까지 확정한 것은 아님.

## 최초 설정과 추천 계산의 구분

선택 신체 정보는 입력하지 않아도 핵심 추천 흐름을 사용할 수 있게 설계. 민감도·활동 패턴과 키·몸무게 등 각 입력이 추천에 어떻게 영향을 주는지는 계산 설계에서 명시하고 검증. 입력 항목이 많다는 이유로 정확도 향상을 약속하지 않음. 사용자에게 아직 구체적으로 확인하지 않은 신체 항목(예: 체지방률·성별)은 확정 항목으로 추가하지 않음.

## 최초 사용자 흐름 — v0.1 이력

1. 앱 목적과 제공할 추천 내용을 짧게 소개.
2. 집과 직장·학교 위치를 등록.
3. 평소 출근·귀가 시각, 이동 방식과 걷는 시간, 도착 후 환경을 설정하는 화면을 검토.
4. 더위·추위 민감도를 설정하고 신체 정보는 선택 입력.
5. 아침 추천 알림을 설정하는 화면을 검토.
6. 홈에서 상의·하의·겉옷과 출근·귀가 시점의 추천 이유를 확인.

위 6단계 흐름은 초기 입력량 의견에 따라 v0.2에서 대체한 이전 안입니다. 최신 흐름은 지역 선택 → 기본 추천 → 선택적 출퇴근 맞춤입니다. 매일 같은 내용을 다시 입력하지 않는다는 사용자 요구는 유지합니다.

저장한 두 위치의 출근·귀가 시점 예보를 추천 입력으로 사용하는 방안을 검토함. 경로 검색·실시간 이동 감지·지하철 혼잡도·실내 온도 자동 수집은 현재 확정 범위에 포함하지 않음.

## 후속 디자인 결정 · 2026-11-02

사용자가 날씨 중심 홈, 3D 토이 스타일, 큰 아바타 하나와 대안 미리보기로 차림을 고르는 방향에 동의했다. 기본·더움 피드백과 실제 착장 수정 화면의 방향에도 동의했다. 이는 정적 시안의 방향 동의이며 추천 정확도·기술 구현 완료를 의미하지 않는다.

부재중에 이어서 작성한 지역 선택·기본 홈·시간별·선택 설정·실패/캐시·기록 관리 등은 새 검토안이다. 최신 자료와 미완료 항목은 [디자인 검토 모음 v0.4](DESIGN_REVIEW_V0_4.md)에 모았다. 아바타 외형·개인 옷장·실제 가상 착용·신체 데이터의 계산 적용을 동일 기능으로 취급하지 않는다.

## 이후 확인할 사항

저장할 위치의 상세 수준과 출퇴근 시각의 설정 방식, 아침 추천 알림 시간·요일·내용, 상세 피드백 항목과 강도 설명, 첫 버전에서 제공할 최소 기능. 알림의 정확한 전달 시각과 백그라운드 기상 갱신 방식은 구현 설계에서 별도 검토.
