# 날씨 캐시와 호출 자원 관리

앱 디스크 캐시와 단일 호스트용 서버 SQLite 캐시를 추가했다. 기온별 추천 규칙과 아바타는 바꾸지 않았으며, 개인화 재계산이 날씨 상류 요청을 만들 필요가 없는 경계를 유지한다.

## 앱

- 앱 전용 cacheDir에 서버 주소별 namespace와 지역 ID별 스냅샷을 저장한다. 최대 8지역, 파일당 2MB. Android가 공간 확보를 위해 지우더라도 사용자 지역 설정은 별도 DataStore에 남는다.
- 콜드 스타트는 저장된 자료를 먼저 표시한다. 유효한 예보·실황이 모두 있으면 자동 서버 요청을 생략한다. 갱신이 필요하거나 사용자가 새로고침하면 서버에 요청한다.
- 자동 동시 조회는 직렬화 후 캐시를 다시 확인해 하나의 수집 결과를 공유한다. 원자적 파일 교체로 저장 중 종료 시 기존 파일 손상을 줄인다.
- 부분 응답은 아직 쓸 수 있는 기존 자료를 지우지 않고 이전 자료로 표시한다. 전체 실패·저장 실패도 마지막 정상 스냅샷을 지우지 않는다.
- 파일에서 읽었다는 이유로 fetchedAt·issuedAt·expiresAt를 새로 쓰지 않는다. null과 0, 강수 범주, 누락 시각과 출처를 보존한다. 다른 서버·다른 지역·깨진 파일·모르는 캐시 버전은 섞지 않는다.

## 서버

- 메모리 캐시가 먼저 응답하고, 미스 시 `.cache/weather.sqlite3`에서 복원한다. 공식 제공자·계약 v1, 자료 종류, 격자를 기준으로 저장한다. 같은 격자의 여러 행정구역·사용자가 자료를 공유한다.
- 정상 자료는 다음 발표의 제공 예정 시각까지 재사용한다. 단기예보는 3시간, 초단기실황은 1시간 발표 주기와 현재 가이드의 10분 제공 지연을 사용한다. ‘수신 후 5분/10분’만으로 같은 발표를 재수집하던 동작을 제거했다.
- 같은 격자·자료의 동시 요청은 합치고 상류 동시 수집은 4개로 제한한다. 요청이 없는 지역을 전국적으로 미리 수집하는 배치나 상시 폴링은 추가하지 않았다.
- 최신 발표가 지연될 때 이전 발표를 이미 저장했다면 그 자료까지 다시 내려받지 않는다. 실패는 30초부터 최대 15분까지 단계적으로 재시도 간격을 늘린다. 새 발표는 이전 발표의 실패 간격에 갇히지 않는다.
- SQLite 레코드는 최대 512개, payload 합계 64MiB를 넘으면 오래된 것부터 제거한다. 실제 DB 파일은 인덱스·WAL·빈 페이지 때문에 payload 상한보다 클 수 있다. 메모리 레코드와 실패·요청 제한 맵에도 개수 상한이 있다.

## 신선도·이전 자료

expiresAt는 다음 제공 예정 시각이며, 실제 도착이 늦으면 이전 자료라고 표시한다. 제공자가 같은 발표를 정정했는지 수시로 재확인하는 기능은 이번 정책에 포함하지 않았다.

- 예보: 실제 수신 후 최대 6시간이며 대상 시각 자료가 남아 있어야 한다.
- 실황: 다음 제공 예정 시각 이후 최대 20분, 관측 자체의 나이 최대 90분, 실제 수신 후 최대 90분 중 먼저 오는 제한을 적용한다.
- 위 기준은 서버와 앱에서 함께 적용한다. 이전의 ‘실황은 수신 후 무조건 20분’ 기준을 바꿨다. 같은 실황을 다시 받아 수신 시각만 최신으로 만들지 않기 위해서다.
- 시계가 수신 시각보다 뒤로 이동하면 자료를 유효하다고 간주하지 않는다. 기상 관측과 예보를 서로 대신하지 않는다.

## 호출량·상한

실제 상류 HTTP 요청 **직전**에 KST 날짜별 시도 횟수를 SQLite에 원자적으로 기록한다. 페이지·재시도·실패도 각각 센다. 서버 캐시 적중은 상류 사용량을 소비하지 않는다. 최근 32일 범위의 날짜 집계를 보존한다.

서버 `.env` 또는 환경변수 `KMA_DAILY_REQUEST_LIMIT`에 **실제 계정 승인량보다 여유 있는 양의 정수**를 설정하면 이 서비스의 자체 상한을 적용한다. 빈 값은 집계만 수행한다. 계정의 승인 한도를 확인하지 않은 상태에서 임의의 숫자를 입력하거나 상한이 이미 활성화됐다고 주장하지 않는다.

상한에 도달하면 상류 요청 전에 중단하고 사용 가능한 이전 자료를 반환한다. 한도를 설정했는데 집계 저장소를 열 수 없다면 요청을 보내지 않으며 `/ready`도 실패한다. 이 수치는 제공자 청구/사용량 명세가 아닌 **이 서비스의 요청 시도 집계**다. 같은 키를 쓰는 다른 프로그램의 사용량은 포함하지 않으므로 승인량보다 여유 있게 설정해야 한다.

## 배포 범위

외부 캐시 서비스·새 SDK·인증키의 앱 배포는 추가하지 않았다. SQLite는 현재 단일 호스트에 적합한 구조다. 여러 인스턴스나 임시 파일시스템의 호스팅에서 전역 쿼터·재시작 보존을 보장하지 않는다. 운영 배포 시 영속 저장소와 공유 카운터/락을 확인해야 한다. 현재 외부 배포 변경은 없다.

## 검증

- 서버 42개: 재시작 보존, 같은 발표 재수집 방지, 정확한 발표 경계, 동일 격자 공유, 실패 간격 증가, 부분 실패·만료, 페이지/실패 집계, 동시 예약 상한·재시작 보존·날짜 초기화·저장소 손상·개수/용량 제한 포함.
- Android 41개: 기존 추천·날씨 계약과 디스크 복원, 무네트워크 재실행, 자동 동시 요청, 부분 응답, 잘못된 지역/서버/버전, 파일 손상·개수 제한·저장 실패 포함.
- 디버그·릴리스 빌드·lint 통과. lint 오류 0·기존 경고 12개. 서버 테스트의 기존 Starlette/httpx 폐기 예정 경고 1종은 남았다.
- [실제 에뮬레이터 확인](../design/cache-validation/README.md): 관악구 예보·실황 최초 HTTP 3회, 서버를 끄고 앱 강제 종료·재실행 시 디스크 복원, 수동 갱신 실패 표시, 서버 재시작 후 갱신에도 HTTP 시도 3회 유지·수신 시각 보존 확인.

후속 M5 [출퇴근·민감도](PERSONALIZATION_IMPLEMENTATION_STATUS.md)에서 두 지역 조회를 한 요청으로 묶고 유효한 지역 캐시는 요청에서 제외하도록 확장했다. 전체 Android 테스트는 현재 61개다. 다음 제품 개발은 M6 구조화 피드백·기록이다. 재미 콘텐츠는 [제품 아이디어 후보](PRODUCT_IDEA_BACKLOG.md)로 분리해 보관했다.

실제 검증 후 이번에 시작한 서버·에뮬레이터·Gradle/Kotlin 작업을 다시 종료했다. 디스크에 남긴 날씨는 위 유효기간을 넘겨 최신 자료처럼 사용하지 않는다.
