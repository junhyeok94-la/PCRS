## 승인된 방향과 새 검토안

사용자가 동의한 방향: Android 우선, 대한민국, 최소 초기 입력, 날씨 중심 홈, 3D 토이 스타일, 큰 아바타 하나와 대안 미리보기, 실제 착장·체감의 구조화된 피드백. 동의는 방향에 대한 것이며 개별 수치·문구·세부 디자인까지 확정한 것으로 확대하지 않는다.

## 이번에 정리한 기준

- 첫 실행은 지역 한 곳만 선택한다. 로그인·아바타 꾸미기·신체 정보·알림·생활 패턴을 강제하지 않는다.
- 출퇴근 추천은 집과 직장·학교 지역, 출근·귀가의 **이동 시작 시각**을 받는다. 상세 이동 시간·교통수단·실내 환경은 나중에 선택한다. 경로 전체의 날씨를 예측하는 서비스로 표현하지 않는다.
- 첫 버전은 실제 옷장 등록을 요구하지 않는다. 아바타는 의류 종류·두께와 겉옷 탈착을 설명한다. 색·브랜드·핏 재현이 핵심 추천 목표는 아니다.
- 대안 선택은 후보 확정이다. 실제 착장은 피드백에서 별도로 확인한다. ‘챙겨만 간’ 겉옷을 실제 착용 보온량에 합산하지 않는다.
- 환경·감각·예보 불일치 응답을 분리한다. 한 번의 피드백으로 정확도가 개선된다고 약속하지 않는다.
- 날씨 실패 시 가상 예보를 만들지 않는다. 이전 예보가 있으면 기준·갱신 시각과 상태를 드러내고, 설정·기록은 계속 사용할 수 있게 한다.
- 앱 기능 구현은 아직 진행하지 않는다. 기존 빈 앱과 과거 웹 배포는 그대로 두었다.

## 이미지와 구현 명세의 차이

생성 이미지는 배치·분위기를 판단하는 자료다. 아래는 이미지에서 발견한 수정 사항이며 구현 시 [화면 명세](SCREEN_SPEC_V0_4.md)를 우선한다.

1. 설정 보드의 민감도·알림 하위 화면에 생성된 하단 탭은 제거한다. 하단 탭은 오늘·시간별·설정 루트에만 둔다.
2. 기본 홈에는 피드백 진입도 있어야 한다. 새 기본 홈 보드에서 생략되었으므로 개인화 홈과 동일 위치에 연결한다. 출퇴근 설정을 강제하지 않는다.
3. 개인화 홈에 두 지역이 다르면 출근·귀가 각각의 지역명을 표시한다. 과거 홈 시안의 한 지역 헤더만으로 두 지역을 표현하지 않는다.
4. 원래 피드백 시안의 ‘1/2’ 표시는 제거한다. 실제 단계를 정의하지 않은 진행 숫자를 사용하지 않는다. 초기에는 착장·체감·강도 등을 미리 체크하지 않는다.
5. 민감도 이미지의 파란/빨간 아이콘은 강도 자체를 정확하게 표현하지 못할 수 있다. 명칭·선택 상태를 기준으로 전달하며 색만으로 구분하지 않는다.
6. 알림 OFF 상태에서 보이는 07:00·평일 선택은 편집 예시다. 설정 저장만으로 알림을 켜거나 알림 권한이 허용된 것처럼 표시하지 않는다.
7. 기본 홈의 일출·일몰 등 일부 하단 카드는 이미지 높이상 생략되었다. 전체 세로 스크롤 범위는 홈 명세를 따른다.
8. 그림이 예쁘게 보이는 것과 실제 320dp·큰 글꼴·다크 모드에서 읽히는 것은 별개다. 이 조건의 앱 검증은 아직 수행하지 않았다.
9. 도보 시간 구간의 경계가 겹치지 않도록 ‘5분 미만 / 5~9분 / 10~19분 / 20분 이상’ 등으로 정리한다. 선택한 범주를 정확한 도보 분수로 간주하지 않는다.
10. 선택 신체 정보의 추천 기여가 검증되기 전에는 실제 수집 화면을 활성화하지 않는 방향을 제안한다. 입력이 추천에 활용되는 것처럼 표시하지 않는다. 아바타 체형·얼굴과도 분리한다.
11. 기록 삭제 시안의 ‘선택한 내용’이라는 생성 문구는 ‘모든 피드백 기록’으로 통일한다. 삭제 범위를 흐리게 표현하지 않는다.

## 완성도를 판단할 다음 검토

- 새 보드의 화면 배치와 입력 흐름을 사용자와 확인한다.
- 이동 패턴·선택 신체 정보·기록 목록·초기화·삭제 확인까지 대표 시안을 작성했다. 아바타 꾸미기, 기록 상세 편집, 경험 시점 수정 등은 동작 명세를 작성했으나 새 스타일의 개별 시안은 아직 없다.
- 위험 기상 경보의 우선 표시, 장소 검색의 빈 결과/로딩, 저장 실패·알림 거부 등은 명세에 정리했으며 상세 시각 상태를 이어서 확인해야 한다.
- 공급자·비용·상업적 이용 조건·캐시·필요 자료 지원, 추천 계산과 개인 보정 효과는 미확정이다. 화면 예시로 기술적 검증을 대신하지 않는다.
- 실제 의류 에셋의 일관성과 조합 비용을 검증한 뒤 구현 방식을 선택한다. 3D 엔진은 확정하지 않았다.
- 기존 Figma v0.3은 텍스트 중심의 이전 흐름 자료다. MCP 한도로 최신 이미지·화면 명세를 Figma에 옮기거나 재검수하지 않았다.

다음 작업은 새 시안의 핵심 수정 → 필수 상세 상태 정리 → 의류 에셋 제작 검증 → 클릭 가능한 전체 흐름 검증이다. 이 단계가 끝난 뒤 앱 구현을 시작한다.
