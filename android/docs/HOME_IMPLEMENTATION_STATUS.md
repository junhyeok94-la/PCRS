# 지역 기본 홈 구현 결과

캐시 후속 변경: [앱·서버 영속 캐시](CACHE_IMPLEMENTATION_STATUS.md)를 추가했다. 아래 메모리 전용·실황 수신 후 20분 설명은 초기 정책이며 최신 보존 기준을 우선한다.

후속 진행: [지역 기본 추천](RECOMMENDATION_IMPLEMENTATION_STATUS.md)을 연결했다. 아래는 추천 연결 전의 홈 1차 구현 기록이며 ‘착장 예시’ 설명과 캡처는 당시 상태다.

2026-11-02. 실제 Android 앱을 독립 날씨 서버에 연결했다. 이번 범위는 M0 골격 정리, M1 수동 지역 검색·저장, M2 실제 날씨 표시다. 개인 추천·출퇴근 설정·피드백은 다음 기능 단위다.

## 구현한 동작

- 첫 실행에는 지역 하나만 검색·선택한다. 결과 확인 후 저장하며, 취소한 변경은 반영하지 않는다. 위치 권한·로그인·개인 정보 입력은 요구하지 않는다.
- DataStore에 지역 ID와 이름을 저장한다. 앱 프로세스를 종료한 뒤에도 복원한다.
- 오늘 / 시간별 / 설정 3탭. 다른 탭에서 Back은 오늘로 돌아온다. 지역 변경 화면은 취소 가능하며 탭별 스크롤 상태를 보존한다.
- 홈에 지역 대표 관측 기온, 예보 하늘 상태, 제공되는 일 최저·최고, 12시간 흐름을 표시한다. 관측과 예보 시각을 각각 표시하며 누락은 `—`로 둔다.
- 스크롤 아래에 아바타 착장 예시, 습도·풍속·풍향·예보 강수확률·관측 1시간 강수량과 출처를 표시한다.
- 시간별 탭은 최대 36시간의 실제 자료, 첫 24시간 기온 그래프와 날짜별 수치 목록을 제공한다. 자료가 끊긴 구간을 연결해 그리지 않는다.
- 로딩·자료 없음·부분 실패·이전 자료·재시도를 구분한다. 임의의 날씨나 추천으로 실패를 채우지 않는다.

아바타는 승인한 3D 토이 스타일의 투명 PNG 두 장을 사용한다. 겉옷 없음/재킷 예시를 전환할 수 있다. **‘착장 예시 / 현재 날씨에 대한 추천이 아닙니다’**를 명시한다. 추천 엔진과 의류 자산 전체를 구현한 상태는 아니다.

## 데이터·실행 경계

앱 → 독립 날씨 서버 → 기상청 순서다. 공공데이터포털 키는 서버의 무시된 `.env`에만 있고 APK에 넣지 않는다. 서버 실행은 [weather_api 안내](../../weather_api/README.md)를 따른다.

디버그 기본 주소는 `http://10.0.2.2:8010`이다. 에뮬레이터에서 PC의 `127.0.0.1:8010`에 접근한다. 디버그의 평문 허용 대상은 `10.0.2.2`, `127.0.0.1`, `localhost`로 한정한다. 필요하면 Gradle 속성 `weatherDebugApiBaseUrl`로 HTTPS 개발 서버를 지정한다.

릴리스는 `weatherApiBaseUrl`의 HTTPS 주소를 별도로 지정해야 한다. 기본값은 비어 있으므로 현재 릴리스 APK는 서비스 배포용이 아니다. 디버그 네트워크 설정과 전용 검증 Activity는 릴리스에서 제외된다. 홈용 `avatar_preview_*` 두 장은 main 리소스로 포함한다.

지역은 영속 저장하지만 날씨는 메모리에만 둔다. 갱신 실패 후 기존 자료는 예보 수신 후 최대 6시간, 실황 수신 후 최대 20분 및 관측 후 90분 범위에서만 표시한다. 만료·실패는 이전 자료로 표시한다. 앱을 종료해 자료가 사라졌다면 오프라인 재실행 시 재시도 화면을 보여 준다.

## 검증

- API 37 에뮬레이터에서 서울 → 강남구 선택 후 실제 관측·36시간 예보 표시와 스크롤·3탭을 확인했다.
- 앱 강제 종료 후 지역 복원, 지역 변경 화면 취소, 다른 탭 Back 복귀를 확인했다.
- 이 작업의 로컬 서버를 중단해 기존 자료 갱신 실패 안내, 오프라인 재실행의 자료 없음 화면을 확인했다. 서버 재시작 후 실제 자료를 다시 불러왔다.
- 320dp 폭, 글꼴 배율 1.3, 다크 모드에서 홈과 아바타를 확인했다. 검사 후 기기 설정은 복원했다. 모든 화면·Android 버전·TalkBack·실기기 검증을 완료했다는 의미는 아니다.
- JVM 데이터 계약 테스트 13개: null과 0, 강수 범주, 시각, 지역 불일치·샘플·계약 거부, 부분 자료, 만료·오프라인 보존 한계 등을 검증한다.
- `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleRelease` 통과. 테스트 13개 실패 0, lint 오류 0·경고 12개(의존성 버전·백업 등)가 남았다. 보고서는 `app/build/reports/`에 생성한다.

실제 화면 캡처는 [구현 화면 모음](../design/implementation/README.md)에 있다. 관측값과 예보는 촬영 시점의 자료이며 최신 날씨 안내용이 아니다.

## 다음 개발 단위

M3: 지역 기본 추천의 의류 종류·두께·겉옷 탈착 기준과 이유를 구현한다. 온도 하나로 개인에게 맞다고 단정하지 않고, 자료 누락·강수·바람·시간 변화에 대한 경계를 먼저 정한다. M4에서 추천 결과와 지원 가능한 아바타 자산을 연결한다. 이후 출퇴근·민감도 선택 설정, 구조화 피드백, 제한된 개인 보정, 아침 알림 순으로 확장한다.
